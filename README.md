# 📖 О проекте:

Проект содержит автоматизированные UI-тесты для формы авторизации на учебном стенде: 
[QA Guru](https://qa-guru.github.io/one-page-form/login.html)
[QA Guru](https://qa-guru.github.io/one-page-form/automation-practice-form.html)

**Реализованные сценарии:**
- ✅ Позитивный вход с валидными данными.
- ❌ Негативные сценарии (неверный логин/пароль, пустые поля).
- 🛡️ Проверка безопасности (SQL-инъекции, XSS, JSON-инъекции, спецсимволы).
- 📏 Граничные значения (длина логина и пароля).

# Почему его неудобно менять:

- Дублирование локаторов. Если разработчик изменит ID поля с login-input на username, вам придется менять его в 
  нескольких местах (в переменных класса).

- Смешение логики. В одном классе лежит и настройка браузера, и поиск элементов, и сами тесты. Если вы захотите 
  протестировать другую страницу (например, форму регистрации), вам придется копировать весь этот класс и менять
  локаторы. Это нарушает принцип DRY (Don't Repeat Yourself).

- Сложность масштабирования. Если тестов станет 100, а страниц — 20, ваш файл превратится в кашу, в которой невозможно 
  найти нужный элемент.

# Как это можно исправить? Нужно использовать паттерн Page Object Model (POM). Он разделяет код на две части:

- Класс Страницы (LoginPage) — хранит только локаторы и методы (ввести логин, нажать кнопку).

- Класс Тестов (TestLoginForm) — хранит только сами проверки (assert), используя методы страницы.
